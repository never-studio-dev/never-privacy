Privacy Policy

Effective Date: September 17, 2026 · Application: Never · Version 1.0

1. Overview and Core Principles

This Privacy Policy outlines the standards and practices implemented by the mobile application Never ("the Application") concerning user privacy and data handling.

The Application is built upon a strict Local-First architecture adhering to Privacy by Design and Privacy by Default principles as defined under the General Data Protection Regulation (GDPR - Regulation EU 2016/679) and Google Play Data Safety guidelines.

2. Data Collection and Local Storage

The Application operates without any remote data transmission:

  • No User Accounts or Cloud Servers: The Application does not support, require, or maintain user registration, authentication credentials, or proprietary cloud synchronization.
  • Exclusively On-Device Storage: All user-generated content — including workout routines, exercise plans, sets, repetitions, weight records, personal notes, preferences, and optional profile pictures (stored solely within the app's local sandbox storage for UI avatar display, without any external server transmission) — is stored strictly within the physical device's local storage.
  • Hardware-Backed Encryption: Local application databases are secured utilizing hardware-backed AES-256 encryption (via SQLCipher) with cryptographic keys managed by the Android Keystore system.
  • Absence of Network Permissions: The Application does not declare or request the android.permission.INTERNET permission in its AndroidManifest.xml manifest. It is technically impossible for the Application to open socket connections, transmit telemetry, or transfer data over external networks in the background.

3. Voluntary Support and User Communications

The Application includes features allowing users to voluntarily reach out for customer support, bug reporting, feature proposals, and exercise database corrections:

  • User-Initiated Communication: Contacting support is entirely voluntary and is executed exclusively through external email client applications installed on the user's device via standard mailto: system intents. The Application itself does not directly transmit email messages or connect to external mail servers.
  • Pre-Filled Diagnostic Information: To assist in troubleshooting technical bugs and crash reports, the Application pre-populates the generated draft email with non-personal technical diagnostic parameters (device manufacturer/model, Android OS version, app version, and selected category). Users retain complete control over the draft email and may review, edit, or delete any information prior to sending.
  • Purpose of Use: Any information received via email is utilized strictly for technical troubleshooting, customer assistance, and improving the Application. Inquiries and contact details are never sold, rented, leased, or shared with third parties.

4. Tracking, Advertisements, and Third Parties

Regarding third-party integrations and analytics:

  • Zero Trackers and Analytics: The Application does not incorporate third-party tracking libraries, SDKs, or profiling tools (such as Google Analytics, Firebase Analytics, Meta Pixel, or commercial equivalents).
  • No Commercial Advertisements: The Application contains no third-party banner ads, interstitial networks, or programmatic advertising systems.
  • No Data Monetization: No user data is ever sold, licensed, leased, shared, or made available to commercial entities or third parties.

5. Android Operating System Permissions

The Application requests system permissions solely for the mechanical operation of workout timers, reminders, and system continuity:

  • POST_NOTIFICATIONS: Allows ongoing status bar and lockscreen updates for active chronometers, countdowns, and rest-completion alerts.
  • POST_PROMOTED_NOTIFICATIONS: Enables prioritized delivery of workout notifications on compatible Android versions.
  • SCHEDULE_EXACT_ALARM: Required to schedule second-accurate rest alerts between workout sets and planned daily workout reminders in compliance with Google Play alarms policy.
  • RECEIVE_BOOT_COMPLETED: Used solely to restore and reschedule active reminder alarms after the device is rebooted.
  • FOREGROUND_SERVICE (specialUse): Ensures persistent, uninterrupted timer execution while the Application is minimized or the screen is locked, including interactive controls on supported lockscreen surfaces.
  • VIBRATE: Triggers device haptic feedback when a countdown concludes.

None of the permissions listed above access personal identification, location coordinates, address books, media libraries, or external user files.

6. Data Deletion and User Rights

In adherence to Google Play policies and statutory data protection rights (GDPR):

  • In-App Data Purge: Users can permanently and instantaneously wipe all stored records and files (including database entries, preferences, and local profile photos) at any time via Settings > Privacy & Data > Local Data Deletion (Delete all data).
  • Application Uninstallation: Uninstalling the Application from the operating system irreversibly and automatically erases all local database records, preferences, and cached application files.
